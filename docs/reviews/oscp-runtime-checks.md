# OSCP runtime qualification

Date: October 25, 2026. Scope is the [bounded CRT/phone runtime](../21-oscp-runtime-prototype.md), not completed TERM acceptance or the full management game.

The workstation now opens in a faux CRT housing, and the field client has separate handset framing. Both use native registered applications, the same validated personnel services, acquired records and known local plan. The OSCP entry scene can run without local-play renderer nodes. The attached shell reuses the field host's simulation; `SimulationRuntime` is the one tick adapter in either host. No second world or tick loop is created by opening a device.

Two design questions were resolved directly by the user: the phone automatically pauses single-player, and orders prepared there send on closing. The shell owns only a pause it introduced. Existing manual pauses remain; accepted prepared intents can remain pending while physically paused. Drafts change no world state, can be cleared, and are checked again at close. Device, link and actor authority remain host validations. Local tactical holds cannot be bypassed by the prepared-intent path.

`python3 tools/run_spatial_scene.py --check` passes **19,619 assertions**, with zero compiler warnings/errors, including **29 OSCP assertions**. These cover catalog/profile alias resolution; remote workstation rejection; phone submission, delivery and outage/recovery; acquired-record cache and eviction; no mutation from queries/rejection; inaccessible/unpowered devices; prepared intents during a pre-existing pause without physical progress; detached invalid-save isolation; matching older saves without invented phones; and once-only unverified regional intake on the continuing world clock.

The standalone `--oscp-smoke` exercises actual Enter in the command editor, repeated command editing after profile switches, real acknowledgement, continued workstation clocks, phone pause/ownership, no authoritative draft mutation, clearing drafts, submission on close, rejection after link loss, a retained pre-existing manual pause, handset loss/recovery, profile restrictions, offline cached records and Escape while the editor has focus. Captures include the CRT, phone communications, offline view, local plan and prepared orders. The regional R-017 message is an authored SCiPnet source claim; it does not create an SCP, establish truth or deploy personnel.

The attached `--operation-smoke` passes actual E/terminal approach/T access, real acknowledgement, save round-trip and the existing unseen-occupant navigation fixture. It additionally opens the phone with P, verifies automatic pause, sends field-action keys and a covered field mouse click without world mutation, prepares a local draft and uses Escape to submit/resume. The legacy `--smoke` passes movement, observation/relocation, held clocks/save, exact look stop, discovery cue, diagnostic/art toggles, sight shading and the compact wall-only cutaway.

Rendering builds pass with zero compiler warnings/errors. The virtual display uses llvmpipe and retains the nonfatal unsupported V-Sync warning; no large-site performance or export qualification is implied. Documents/local links/fences and the Python launcher syntax are checked separately.

Current handset/radio/power/authority services are bounded fixtures, not inventory-backed hardware, charge drain, full employment or full SCiPnet security/routing. CRT assets are original Godot-drawn presentation; SCP-derived prose/style references remain credited through the source/design registers. Full infrastructure/construction/logistics, resident AIC runtime and optional model provider, case triage/editing/deployment, surveillance attention and a phone/inventory split remain future work.
