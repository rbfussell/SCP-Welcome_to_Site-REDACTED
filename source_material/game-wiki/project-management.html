Software project management

Implemented tooling, not an in-world system. The game is in Project/ under a portable harness workspace. It retains its Git repository, engine layout, assets, canon checkout and GitHub Pages workflow. A standalone game clone remains supported.

The active software-game profile tracks bounded slices, dependencies, blocking questions, wiki/document reading notes, actual command logs, accepted input hashes and explicit self/independent review. One developer can perform the responsibilities; there is no mandatory manufacturing crew or artificial restart of accepted design. Optional specialists require explicit delegation. This is not a claim of independent Internal Affairs or completion of the separate generic harness's strict preflight.

Connected authorities

  • Implementation ledger: what the game currently proves and leaves open.
  • Development and wiki consistency: required reading, maintenance, cross-links, generated-page inspection and final semantic consistency gate.
  • Development and version control: Git, checks, existing remote and public documentation publishing.
  • Integration contract: adapter behavior, portability and verification boundaries.
  • Management guide: commands and source-of-truth map.
  • Engine: shared simulation remains authoritative for game behavior.

The board does not replace mechanics pages, canon provenance, ADRs or scope gates. Existing results imported from cac3555 are historical; M0 remains open. Proposed backlog work is not implemented behavior or approval to expand scope. No management record becomes knowledge available to characters, OSCP or an AIC.

Evidence and limits

Completion needs passing tests/docs/wiki-build/wiki-check command records, unchanged declared source inputs, intact logs, a wiki check after rebuilding, acceptance coverage and explicit semantic review. Reading notes and review are attestations; hashes do not prove that someone read a page or that a command tests the right thing. Self-review does not imply independent review. The CLI is a single-coordinator local tool, not a concurrent service or authenticated chain of custody.

The authoritative tools/profile/overlay live in the game Git repository. The outer entry point is reinstallable from those templates. The outer harness's original strict workflow and JSON publication store remain separate; they do not replace this game wiki. Evolving task/log records are retained in management/ rather than copied into generated mechanics pages. This prevents circular evidence hashes.
