Worn container drops

Implemented bounded reference-body interaction, November 5. I → Sprites accepts drops into the real backpack main compartment and utility-pouch interior through registered visible bag material. This extends sprite equipment drops, worn backpacks, worn attachment chains and independent transfers. See the runtime/metadata guide. This is ordinary equipment, not SCP canon.

Material and intent

Optional PaperdollPart.dropRegion links actual illustrated material to a real ordinary compartment. Backpack bag parts name main; harness parts name none. The pouch names inside. Topmost per-part alpha picking shares the current side, masks, source crop and attachment transform. Front/back mounting selects the bag side normally. Transparent gaps and unregistered garment material do not offer storage. Tint is drawn within normal outfit order, preserving later occlusion and packed-content privacy.

The provisional first-version precedence is exact mount → registered container → free body fit. The user was asked about this optional UI preference; this implementation choice is not a settled permanent design rule unless confirmed later. Closed/full container refusal never falls through to equipping clothing or choosing another pocket. R over container material leaves body/mount drafts unchanged; normal packing chooses a legal stored orientation.

One normal transaction

Storage targeting supplies an item/compartment ID. The sprite surface reuses the existing packing quote and AutoPlace action. Compartments must already be open/accessibly unsealable; there is no free opening, source search or hidden-content view. Normal free-fit/scoped-rearrangement rules, time/AP, access, load, cycle rejection, source retention and commitment revalidation remain authoritative.

Source/destination trails remain unchanged, allowing direct source-grid-to-worn-pouch transfers with an occupied hand. Ground storage remains a separate physical staging location. Invalid/paused release changes nothing. Current schema-15 continuation gains no new fields or kit identity; source PNGs and native definitions are unchanged.

Evidence and limits

Native checks cover bag-only versus harness targets, closed/paused/full/self refusals, paid source retention/exact restore, retained source views, pouch transfer and both backpack mount sides. Focused --worn-storage-smoke and paperdoll/full inventory modes run the fixture. See actual results; wiki generation does not run gameplay checks.

Other body pocket segments, on-sprite closure animation, general body variants, compartment selectors, new packing algorithms and world outfit composition remain future work. Enlarged gear/contents views retain explicit pocket choice and fastening controls. Asset organization and the item catalog expose registration evidence without changing physical authority.
