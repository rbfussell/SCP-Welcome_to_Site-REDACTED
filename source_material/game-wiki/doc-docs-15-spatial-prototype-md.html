First Godot spatial scene

Status: Runnable M0 spatial/observation subset, updated October 23, 2026. A native SCP-650 observation/relocation module now runs in the scene. A bounded orders/OSCP/trolley recovery proof is now available; complete facility operations, procedures, script hosting, combat and the full M0 gate remain open.

Run and verify

From the repository root:

python3 tools/run_spatial_scene.py
python3 tools/run_spatial_scene.py --check
python3 tools/run_spatial_scene.py --smoke work/preview/spatial-scene/scene.png

The launcher uses Godot .NET 4.7.1 and the .NET 8 SDK selected by global.json. It finds godot-dotnet on PATH; alternatively pass --godot /path/to/the/mono/executable. The regular non-.NET godot cannot run this scene. First restore requires the Godot SDK packages from NuGet unless already cached. The asset generator uses Python/Pillow.

This workspace's colon/brackets caused direct Linux MSBuild import failures and a .NET app-host initialization failure even through a symlink. The launcher copies only game, src, tests and global.json to a temporary directory, builds/runs there and removes the copy on exit. It never copies the wiki archive or Git history. Edit this repository's source; temporary runtime files are disposable. Persistent prototype saves remain under ignored user-data/, and import/tool logs under ignored work/preview/spatial-scene/. The launcher installs no engine or global SDK configuration.

Tested: Godot 4.7.1.stable.mono.official.a13da4feb, .NET SDK 8.0.128, runtime 8.0.28, Linux, compatibility renderer. Other platforms, exports and performance budgets remain M0 work. The visual smoke run uses xvfb-run when available, otherwise a desktop display; this sandbox requires access to display sockets outside its default restrictions.

Encounter presentation

GroundView renders the existing floor textures through subdivided meshes. Shared world-space shading samples and interpolation soften the cosmetic cone across tile boundaries, avoiding whole-tile brightness changes from sprite anchors. Cone/range fade uses the shared sight constants, but only exact perception decides entity visibility and anomalous observation. Shading rebuilds only when relevant avatar, eye, lighting, door or view-mode state changes; rendering an unchanged held scene reuses it. This is presentation shading, not a flashlight, new sensor, or electrical/HVAC system.

FieldPresentation filters dynamic bodies and consumes only fresh avatar startled events. It never draws RNG, mutates the world, counts a viewport as observation or cues a hidden relocation/remote witness. Restore resets the consumer baseline so historical events do not replay. Local-clock caption/border progress waits during a local hold.

EncounterAudio generates quiet room ambience and a short low discovery accent as presentation-only audio, with mute support and no NPC hearing event. EncounterOverlay provides a readable discovery caption and subtle border, without flashing or camera shake. R disables the border; sound/captions remain independently useful. Preferences currently last for the running scene, not across launches. The atlas is fixed-view first-pass art, not a finished six-direction character set or qualified furniture-pose attachment system.

Fallout 2 mapping comparison

Rechecked the primary CE tile implementation, map definitions, object record and object rendering/blocking. This is a reimplementation reference, not original Interplay source. No game assets or repository source code were imported.

Concern Reference finding This scene
Ground Square floor/roof layer separate from objects Square construction-plane cells beneath walls/objects; roof rendering not implemented
Floor projection Basis (48,-12) and (32,24) Same basis at reference scale; camera zoom applied afterward

Hex spacing Six neighbors including (32,0) and (16,12) Axial bases (32,0) and (16,12), four hex areas per floor-cell area
Walls Separate hex-located objects with elevation and image offsets Short U/V wall sprites with hex-registered endpoints, separate anchors and optional visual cutaway
Blocking Blocking critter/scenery/wall at a hex, flags and neighboring multihex checks Blocked cells from physical footprints, plus wall-segment crossing rejection between free cells
Sprites Project hex, add offsets, place image at bottom-center ground anchor Generated anchor manifest; short wall segments/objects/actors sorted by projected ground depth

Our registration is u=q/2, v=r/2+q/4. Projection gives x=32q+16r, y=12r. Floor corners are (0,0), (48,-12), (80,12), (32,24). Wall artwork follows the projected construction axes; the ground art is not the movement grid. The white overlay shows actual blocked hexes and solid wall segments, not sprite silhouettes. Opening a door updates path and sight obstruction together.

Explicit wall-segment collision is our extension. This is not a bit-exact recreation of Fallout's mapper, collision or formats, and it adopts no fixed 200×200 map limit. See the original research.

Implementation and evidence

The plain C# core owns 50 ms steps, committed movement, independent facing, occupancy reservations, door validation, a bounded NPC patrol, local/world progress and a countdown fixture. The map defines two rooms/corridor, three doors, cabinet, crate, actors and a native SCP-650 instance. Godot input/UI and rendering consume this state without controlling movement through animation callbacks.

The asset generator makes deterministic original raster stand-ins and frame/anchor metadata, including six discrete SCP-650 poses. A separate appearance manifest binds the six textured atlas regions/scales/anchors without changing pose identity or gameplay. F4 retains the diagnostic-art path; regeneration of stand-ins does not overwrite the new atlas. Asset provenance records its source and limitations. --walk-frames N changes presentation without changing movement duration. This is diagnostic artwork, not final production art. Schema-4 saves preserve optional operation state and awareness settings, acquired evidence/acknowledgements and stopped fractional edges, while retaining content identity, actor routes/segment progress, facing/attention/blinking/reactions, patrol continuation, doors/lighting, separate clocks/holds, anomaly bodies, module RNG/deadlines and trace. Invalid incompatible state is rejected before commitment; general content migrations and branch restart are not implemented. Earlier outer-schema-1 or SCP-650-module-schema-1 prototype saves are rejected with an explanation and remain untouched unless the user explicitly overwrites them with a new save. Matching spatial-only outer-schema-2/3 saves with the current module schema upgrade to outer schema 4; schema 2 receives an empty awareness ledger and both safety settings enabled. The operation profile has a distinct content identity and requires its operation snapshot. The SCP-650 module schema remains 2.

Engine-independent checks cover source-derived projection vectors, positive/negative hex picking and polygon interiors, door path/sight changes, permitted-step wall crossings, mid-segment persistence/replay, held local timers with continuing world counters, global manual pause, attention-preserving movement and invalid-save rejection. Dedicated SCP-650 checks cover direct observer profiles, commit-time validation, destination occupancy/visibility, cross-door relocation, no-candidate retry, unchanged observed poses, one reaction per witness/encounter and module save/hold behavior. Additional complacency checks qualify per-person flags, threat/relaxed geometry across fixed seeds, host rejection and persistence. Field presentation checks verify direct sight and one-shot avatar feedback without world mutation. Godot smoke input checks the exact clicked destination, O attention loss and relocation, F6 hold, continuing world and module restoration, then a reproducible avatar look-away/RMB discovery fixture, one cue, J flag change while observed and F2/M/R controls before capturing field and diagnostic viewports.

Visual inspection confirmed the skewed perspective, direction/state labels, collision overlay, cutaway and visible controls. A click-coordinate mismatch was caught and fixed by transforming the input event's own viewport position. Mesa software rendering was used; this is not a performance qualification.

The SCP-650 verification record records the current module/input checks, observed results and their limits.

F8 currently changes a shared lighting boolean. Electrical circuits, backup supplies, room temperature, HVAC and qualified utility maintenance are not implemented. Their staged contract is facility infrastructure.

Remaining work includes generalized multi-floor/split-sprite occlusion, production art scale, critical events under detail changes, script isolation/quotas, domain transfers, AP/initiative and incoming cross-zone arbitration. The bounded operation proof now supplies received OSCP records, delivered personnel orders and timed observed-trolley recovery. Full SCP containment/transport procedures, human-attended surveillance, employment/logistics/general OSCP integration and the complete player knowledge/sharing model are not implemented. The code map documents the actual system boundaries, and item composition records future inventory/crafting architecture. This proof does not certify the full rows in scope and acceptance.

Click-to-move obstruction handling — October 23

A valid in-map click keeps its requested destination. Use a complete route when one exists; otherwise approach the closest reachable boundary instead of rejecting a distant click on an occupied or inaccessible point. The field preview uses the known fixed facility layout and directly perceived actors/anomaly bodies/movable equipment. Unseen occupants and anonymous reservations cannot silently veto the click or alter its preview. The field hover readout says NO KNOWN BLOCK rather than exposing hidden collision state; diagnostics retain authoritative geometry.

Actual movement still revalidates collision and occupancy before every step. An encountered obstruction can supply an identity-free cell to avoid for this movement command. Try an alternate route to the same destination; if none gets closer, stop before the obstruction with ordinary blocked-path feedback. Do not overlap the body, disclose its identity or pause either clock. An occupied goal itself remains unreachable until it clears. If access opens during an approach, retain the original destination and continue through a newly valid route. Explicit cancellation and anomaly-awareness stopping clear that continuation.

PlayerNavigation separates this planning view from MovementSystem's physical checks. NPC work and rig plans retain their existing validated routing; this change applies to player click travel. Fixed walls/doors/props still use the prototype's known-plan model, not a finished exploration/door-memory system. Route-local encountered cells are cleared on completion/cancellation/stopping rather than acting as a permanent obstacle map.

Optional actor fields MoveGoal and BumpedCells are saved/validated within outer schema 4. Older matching snapshots without them retain their committed route endpoint; new commands supply the explicit destination. Unknown future route occupants remain legal in a save, while physical step execution checks them on arrival. Pathfinding checks cover dark/visible occupied goals, actual approaches/stops, vacated destinations, walls/opening access, contact-driven detours, cancellation and saved intent. The operation render fixture additionally submits a real Shift-click into an unseen occupied corridor hex and verifies travel followed by a safe stop.

Lowered-wall view

W, or the wall-view button near the top of the field panel, switches between full-height walls with the existing local cutaway and short bases across the entire map. The View tab also provides a Lower all walls toggle. The base is approximately 31% of full height, cropped at the dark lower panel of the current wall texture rather than squashing the full image. A small cap follows the lowered top edge. Diagnostic artwork supports the same mode. Doors, open door frames, props and people retain their normal appearance.

The local feather is dormant while every wall is lowered; returning to full height restores the current H preference. This is presentation state only: collision, pathfinding, observation, concealment, anomaly rules and save data do not change. Lowered walls make already-permitted characters and objects easier to read without revealing unseen entities. The setting currently lasts for the scene session.

The native spatial smoke captures full, lowered, restored and diagnostic-lowered views, checks W and the actual field button, verifies all ordinary walls are lowered while doors retain full height, and compares unchanged world/save state, sight and walkability.
