# Inventory object sprites

Generated October 25, 2026 with the built-in `image_gen.imagegen` tool, one transparent-background request per object. These are game-project assets, copied into this directory; runtime does not depend on the generator cache.

The [manifest](manifest.json) records each original output path, exact subject, common full prompt template, unmodified PNG size, alpha range and crop region used by Godot. For the original eleven objects, combining `promptTemplate` with the asset's `subject` reproduces its exact submitted prompt. The four clothing additions preserve their complete prompt per asset and in [wear-prompts.json](wear-prompts.json). The PNGs are original tool outputs; registration selects an opaque-silhouette bounding region without rewriting image pixels. Nearest filtering retains texture; the gum-wrapper binding has a presentation-only base orientation adjustment.

Objects: secure phone, site radio, backpack, trousers, coat, flashlight, dressing packet, utility case, gum packet, gum piece, inert training weight, work shirt, wool socks, work shoes and chemical coverall. No icon backgrounds, rarity cards or copied inventory-interface art are used. Physical dimensions, occupancy, access and AP/time are defined independently in the simulation content. Replacing artwork cannot change packing or gameplay identity.

These are development stand-ins. They are separate from the six-facing character sheets and do not yet change the actor's rendered clothing or play handling animations.

## Gear-view segments

`hotspots.json` contains hand-traced contours registered against each manifest **cropped sprite**, using normalized coordinates: `[0,0]` is its top-left, `[1,1]` its bottom-right. They were traced by inspecting the existing PNGs on October 26, not generated by an automatic segmentation model. Original image pixels remain unchanged.

Each entry supplies a physical `region` (or null for the garment's front fastening), a hover label, an ordered simple `polygon`, and an interior `hitPoint` used by native input checks. The same sprite transform handles fitting/centering and the gum packet's base rotation for drawing, picking and highlights. A hover highlight redraws the selected textured polygon through the original sprite alpha. Unhovered segments have no box, persistent outline or overlaid text. Later entries take precedence where visible segments overlap.

When replacing/cropping artwork, retrace its contours and review both hover captures and actual context/double-click input. Keep physical region IDs stable. Core checks reject out-of-bounds, degenerate and self-crossing contours; Godot checks qualify actual source-to-screen mapping, blank-space rejection and resize alignment. The current backpack binds only its main and side compartments; extra visible pouches/straps await their gameplay definitions. Attachment-surface fitting/rendering and state-specific open/flap illustrations remain separate work.

The coverage slice rebinds the trouser image to four real compartments: hip seams (`left`/`right`) and the visible lower pouches (`cargo-left`/`cargo-right`). The source PNG is unchanged. Hover tint reads physical access coverage; body-local mouth/cover geometry is authored separately from these image contours.

## Belt / utility pouch stand-ins

The [placement-extender slice](../../../docs/37-placement-extenders-and-mount-points.md) adds `utility-hook.png`, generated with the built-in image tool on October 29. Its exact prompt is in [attachment-prompts.json](attachment-prompts.json) and its original source path, RGBA dimensions and atlas registration are in [manifest.json](manifest.json). The original PNG is copied without pixel changes. Its upper clip anchor and 88-pixel mounted height match both drawing and alpha picking; a separate lower physical point is authored in native content. `hotspots.json` binds its exterior region. Tiny mounted sprites retain the item pressed when starting a drag, so crossing the drag threshold cannot lose the original target. Provider views draw and pick visible descendants with the same composed six-direction transforms.

The built-in image generator produced `utility-belt.png` and `utility-pouch.png` with real transparency. [Exact prompts and tool mode](attachment-prompts.json) and [source/alpha/atlas registration](manifest.json) accompany the unchanged source PNGs. Both assets were visually inspected. Atlas regions exclude faint transparent-margin noise; no background was painted into the originals. The pouch flap is a source-image interaction segment; mounting occupancy lives separately in simulation metadata.

Mounted illustrations now use `attachmentIllustrations` in the manifest: height, normalized mounting anchor and baseline rotation. The pouch’s strap anchor and source-relative sixth-turn rotation drive preview, rendering and alpha picking together. Its source offset is 0°: upright at mount 0°, inverted at 180°. Physical occupancy remains an independently authored hex shape. This is registration metadata over the existing source PNG, not regenerated artwork.

The utility pouch's physical footprint uses the mounting cell plus the two symmetric lower neighbors in the point-up grid. The symmetric lower pair centers its envelope on the upright source axis, so both physical occupancy and artwork advance through the same sixth-turns. This physical shape is authored in `field-kit.json`; the art manifest supplies no compensating half-step offset.
