Simulation code map

This is the engine-independent C# prototype. Godot input, drawing and diagnostics UI live in game/Presentation (../../game/Presentation; repository path). The public script host, complete logistics/crafting, full profession/calendar systems and complete combat are not implemented yet. Scheduled observation employment is implemented as a bounded slice.

Directory/file Owns Does not own
SpatialSimulation.cs Tick ordering and validated prototype command entry points Sprite frames, SCP-specific selection policy or inventory rules
World/ (World; repository path) Map definition/geometry, doors, lighting, physical state and dynamic blockers Whether an SCP is allowed to self-relocate
Actors/ (Actors; repository path) Actor state, perceived player-route planning, movement progression, reservations and bounded patrol Perception qualification or anomaly RNG

Persistence/ (Persistence; repository path) Versioned snapshot and detached validation before replacing live state Replaying creation rewards or rerolling modules

The confirmed production presentation is a Fallout 2-style bottom HUD plus a dedicated full OSCP terminal workspace for strategic management. The Pip-Boy comparison concerns interface access, not arm-mounted hardware. Full OSCP is accessed at fixed facility workstations and framed by a visible faux CRT monitor; its secure-phone counterpart focuses on current-location maps, mission information, communications and authorized mission/team commands, with extensible applications and shell navigation still to qualify. Current engineering panels are replaceable adapters: they read acquired feedback/query state and submit validated commands through SpatialSimulation. Keep screen arrangement and interaction bindings in Godot presentation; the simulation owns authority, knowledge, AP, equipment rules and consequences. See the presentation target.

Future OSCP, world-map, local-play and facility-management entry scenes each receive their declared simulation services from an application bootstrap. They must run meaningful standalone scenarios without sibling renderers and attach to one session/scheduler in combined play. Commands, queries, IDs and saved world state stay shared; scene-to-scene widget calls do not implement domain work. ADR-0007 records the accepted direction and proposed contracts. The October 25 OSCP/local proof now uses an attachable OscpWorkspace and a standalone OSCP entry over the same SimulationRuntime tick adapter and simulation services. World-map/facility mode entries remain future work. The OSCP runtime guide records qualification and limits.

Typical path:

mouse/key intent
  -> SpatialSimulation command validation
  -> world/perception facts change
  -> anomaly module evaluates the facts
  -> module proposes a relocation
  -> host rechecks observation + destination + execution gate
  -> one physical body/pose/collision transaction
  -> diagnostic trace and later witness reaction
  -> Godot draws the committed state

The native module interface is an implementation seam, not a sandbox security guarantee or a promised mod API. SCP-650 owns per-person complacency state and selects threat/relaxed placement and pose pools. Its queries request explicit near-actor/radius, optional rear placement, clear-line geometry and unobserved cells. The shared host does not interpret complacency: its generic flag dispatcher forwards a validated target to the module, which accepts/rejects the named flag and actor kind. The host validates those declared parameters within the instance's granted scope. A future module can need another qualified capability; avoid adding its special rule to the movement/rendering code.

Current inventory snapshots use outer schema 15 for persistent map-local ground piles plus actual worn order, attachment poses, worn body coordinates, exact packing plans, per-fastening preferences and queued inventory securing, garment fastening and inventory handling plus employment/journal/tactical continuations and SCP-650 module schema 2. Matching older non-inventory operation/spatial saves retain their explicit compatibility paths; matching schema-14 inventories migrate without ground placements, while inventory schemas below 14 require a fresh scene. The optional operation snapshot persists order/report/rig state and is validated separately. Handset, acquired-report IDs and once-only regional-intake fields introduced in schema 5 remain supported; matching older saves do not gain a new issued handset. Content identity includes the operation definition; the newly appointed employment scenarios cannot load the former scenario saves. Employment continuation is required when the matching scenario defines appointments. Matching spatial-only schema-2/3 saves remain supported; schema 2 migrates with empty awareness history and enabled safety settings; older implicit-familiarity module saves are rejected rather than assigned invented flags. PlayerNavigation plans against known layout/perceived occupants and approaches blocked goals; actual steps retain full collision validation. Requested goals and route-local encountered cells preserve continuation/rerouting without revealing hidden occupants. A stopped actor retains a fractional edge separately from its cleared route, and new paths can continue or reverse without snapping. Shared awareness accepts acquired contacts and never pauses a clock or delegates player safety to the SCP module. Module state stores complacency separately from witness history. No automatic complacency metric exists. A failed restore builds/discards a detached candidate and leaves the current world intact. Do not mutate live state incrementally while validating a save. Read-only diagnostics return current facts without consuming RNG or adding events.

Run the spatial checks and SCP-650 checks with python3 tools/run_spatial_scene.py --check from the workspace root. The prototype guide covers the Godot smoke run and the composition contract records future inventory/crafting boundaries without adding empty implementations now.

The recovery prototype guide describes the command → delivered order → real work → received report flow and the explicit limits of radio/device and physical transport fixtures.

The event log and tactical training guide explains evidence-gated player messages, local AP resolution, controls, provisional tuning and pending-action persistence. The unrestricted debug trace never supplies journal entries.

The generated facility sprite set is selected by the presentation-only SpriteArtCatalog in game/Presentation. Its actor/rig/state/facing/frame/ordered-layer bindings, atlas regions and anchors are independent of this simulation. Baked outfit art can later be replaced by compatible layered assets without changing NPC rules or timing.

The employment guide records local test-shift timing, actual handover, order interruption, acquired staffing information and limits.

The inventory guide records native profile identity, physical/service equipment gates, realtime/AP costs and qualification limits. Definitions are embedded JSON; art stays in Godot presentation.

InventoryWear owns body coverage, layer conflicts, exposed pocket regions and outermost pack dressing dependencies. It is independent of sprite/UI selection. Garment opening is a timed inventory action; world clothing art and protection effects remain future work. Belts, physical overlays and nested hook providers are qualified by the later guides.

Inventory closure intent is isolated in Inventory/Transactions/InventorySecuring.cs. It purchases serial ordinary handling at local scheduler boundaries, including tactical input boundaries. Preparing during pause never advances local time; insufficient AP waits for an explicit later turn. Clothing overlap, access covering and removal blocking are independent metadata. UI view trails and authored hotspot geometry remain in Godot presentation. Independent source/destination inspection now retains accessible source contents while choosing gear; direct transfers still use the same paid transactions and physical access checks.

Inventory/Transactions/InventoryClosures.cs derives action labels from physical closure booleans and resolves authored securing defaults against instance/compartment overrides. Automatic dismissal plans honor those preferences; explicit physical actions remain available. Overrides persist in the item graph but do not change physical access or invalidate already paid work.

Inventory packing is isolated in Inventory/Placement/InventoryPacking.cs (pure bounded region solver) and Inventory/Transactions/InventoryPackingActions.cs (access, costs and plan validation). Exact manual moves retain their original behavior; AutoPlace addresses a different container, and Arrange is explicit. Saved paid work retains the exact atomic plan. See the gear authoring contract for proposed future schemas beyond the current native DTOs.

Body-local mask/contact fitting is isolated under Inventory/Equipment/BodyFit/. The catalog reads a separate embedded silhouette/contact resource included in content identity. Pure geometry returns cells and failed contacts; the bridge validates optional worn poses through existing Move commands, costs and detached saves. Named mounts remain; mapped pocket coverage is now handled separately by InventoryCoverage. See the body-fit runtime guide.

The symmetric body cleanup authors matching body/clothing/mouth/fastening geometry through tools/author_body_fit_fixture.py. Optional linear spans extend a fixed core within declared bounds; wearing and access project resolved cells. Length derives from immutable geometry and saved pose, preserving schema 14 and ordinary paid handling. Central authored webbing points remain distinct from extension.

Inventory/Equipment/BodyFit/InventoryCoverage.cs projects compartment access mouths and active outer cover masks on matching body surfaces. InventoryWear.Compartment feeds that result into every ancestor access check. Unmapped outer gear retains the coarse compatibility rule, and geometric non-overlap does not reapply a coarse block. Removal/layer rules remain independent. See the coverage runtime guide.

The belt/pouch runtime adds Inventory/Equipment/InventoryAttachments.cs: compatible support contacts, local hex occupancy, collision and composed body position. It shares the ordinary hierarchy, placement, access, timed transaction and save services. Exterior attachment regions deliberately bypass square packing and have no lid state.

Placement extenders and mount points add InventoryAttachmentFrames for composed provider coordinates and InventoryAttachmentClearance for shared exterior collision. Worn providers share the actor/surface plane; loose assemblies have separate anchors. Immediate mating contacts have a narrow collision exception. Existing access, hierarchy, load, paid transaction and detached restore checks remain authoritative.

Direct body-fit drops address one inspectable stored item through PreviewBodyFitDrop, leaving the worn/held selector bounded. Both preview paths build the same ordinary Move request; access, time/AP, graph revalidation and continuation remain in existing services. Godot owns independent transient rotation/drag drafts.

Body inspection/removal adds InventoryBodyInspection: read-only exposed own-worn targets, active cover masks, explicit front/back sides and normal move-access feedback. The Godot inspection partial separates item picking/drag sources from fit drafts. Camera mirroring never changes physical pose; removal uses existing paid transactions and clears worn coordinates normally.

The original upper-body sprite qualification introduced a Godot-only appearance adapter without domain state/content changes. Full-body qualification initially added real underwear and six clothing bindings. Later backpack and waist belt/direct pouch presentation extends the Godot adapter to eight direct wearable bindings and one bounded exterior binding. These visual registrations add no domain state or physical content. The native kit has 19 definitions/39 instances/9 fit profiles; the earlier underwear content change requires fresh older-kit saves, with schema 14 unchanged. Visual alpha, body cutouts and paired render parts never determine physical access, fitting, parenthood or mass.

Ground inventory and physical piles resolve empty map-local roots without mutating queries or extending the authored root list. Ground order is separate from worn order; covering blocks direct items and every nested ancestor path. The permanent Godot dock reuses exact grid handling. Current schema 15 preserves floor orders and canonical paid moves, with guarded migration from matching schema 14. Earlier schema-14 statements above describe their original slice qualification. Native kit identity/art are unchanged.
