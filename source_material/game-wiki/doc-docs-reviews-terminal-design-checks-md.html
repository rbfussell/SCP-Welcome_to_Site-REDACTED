Terminal design review — October 22, 2026

Scope: revision 0.6 documentation and the interactive OSCP design preview. No game/kernel, AIC runtime, model API, actual SCiPnet service or Godot integration was implemented or certified by this review.

Documentation evidence

Checked Markdown local links, balanced code fences, unique acceptance IDs and requirement references. At this review, the scope matrix had 85 unique requirements, including TERM-01 through TERM-09; later design passes may extend it. Canon references and original game adaptations are separated in the OSCP/lore documents. Resident AIC presence, deterministic initial duties and future optional local-model JSON integration follow the user's confirmed answer; detailed authority/canon questions remain pending.

Interactive preview evidence

Used bundled Playwright with local headless Chrome against a temporary local wrapper. The in-app browser tool could not initialize because of an environment filesystem-rule configuration error, so this was a browser-testing fallback. No external communications, article software execution or remote publishing occurred.

Checked both carousel layouts and local actions:

  • Director relief produces an accepted/awaiting-acknowledgement receipt while coverage and qualifying sight remain unchanged.
  • Disconnection marks cached information and queues a request locally; reconnection reports that pending requests need revalidation.
  • The outside report retains unverified provenance; requesting assessment does not mark a field team deployed.
  • Security cannot authorize the director's regional assessment; the cafeteria session does not expose the sample case.
  • Technical support shows the resident assignment and illustrative host/provider information; a ticket does not complete a repair or an AIC task.
  • Command buttons and Enter-key entry use the same local intent handler. Fixed a command-entry issue caused by sandboxed browser form submission during review.
  • Layout width checks at 1,024, 736, 360 and 320 CSS pixels found no horizontal overflow of the preview root. Reviewed desktop/light, desktop/dark and narrow renderings. No JavaScript page errors were reported by the completed interaction checks.

These checks exercise illustrative UI behavior, not simulation authorization, authentication, transport, persistence, observer predicates or performance. The role picker is a review control; the game must authenticate an actual actor/device. Offline requests are represented by receipts, not a durable delivery service. The planned model boundary and TERM requirements still require implementation and runtime qualification.
